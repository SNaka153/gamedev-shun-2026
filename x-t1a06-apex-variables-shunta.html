The T1A06 connection · how APEX works

01 / A proper HTML document

<head> holds the title, metadata and styles. <body> holds the interface. A script at the end connects the controls to the simulation. Everything is in this one file and works offline.

The base assignment is linked at the top. This is Shunta's separate X assignment.

02 / Variables with visible consequences

A string stores the athlete's name. Numbers store speed, angle and height. A boolean turns the preview on or off. A function uses these values to calculate a new flight. The live inspector shows the same values the model uses.

03 / A small, transparent model

This is a 2D point-ball experiment: constant gravity (9.81 m/s²), no air resistance, no spin and no sideways motion. The ball begins 0.6 m behind the baseline. Contact below the net top ends the serve as a net fault. This is a simplified game model, not a prediction of a real serve.

x = -0.6 + speed × cos(angle) × time
y = height + speed × sin(angle) × time − 0.5 × gravity × time²

Court length and net-height options use the FIVB 2025–2028 rules, sections 1.1 and 2.1. Target scoring is custom to APEX. A and B retain their own target and net settings.

04 / The original class idea

let myNum = 3;
let myString = ' Hello ';
let myFloat = 17.5;
let myBool = true;
...

3 and 17.5 are both JavaScript number values. A boolean is true or false. With a string, + joins text.

Keyboard: Space serves; ← / → change the angle; ↑ / ↓ change the speed. Shortcuts leave text fields alone. The sliders also work by keyboard and touch.
